# CHECKPOINT 01 — PASS

**Phase:** 01 Core primitives (arena, log, metrics, clock, event loop, channel,
task, util).

## What was done
- **Arena** (`src/core/arena.{h,cpp}`): chunked bump allocator, 16 KiB first
  chunk, geometric growth (×2 to 1 MiB, then +1 MiB), 64-byte data alignment,
  `reset()` O(#blocks), `ScopeArena` guard, zero-copy move. Fill-cursor
  (newest-first) design: O(1) bump, every block reused across resets before any
  growth (steady-state zero churn).
- **Error** (`src/core/error.h`): completed the Phase-0 vocabulary with
  `is_retryable()`, `is_transient()`, `Err::e_overflow = 25` (additive; enum
  unchanged). `error_code` bool == std::error_code convention (`if (ec)` = error).
- **Log** (`src/core/log.{h,cpp}`): per-instance logfmt writer, levels, no
  globals, no heap in the format path, host callback hook.
- **Metrics** (`src/core/metrics.{h,cpp}`): fixed-slot counters/gauges,
  64-exp-bucket histograms, `snapshot()` + `percentile()`.
- **Clock** (`src/core/clock.h`): header-only monotonic + wall-clock.
- **Event loop** (`src/core/event_loop.{h,cpp}`): epoll (Linux) with poll
  fallback, fd registry (add/mod/del), timer heap (one-shot + repeating,
  cancellable), wakeup pipe (slot 0), `run_once(timeout)` with corrected
  deadline/timer interplay.
- **Channel** (`src/core/channel.{h,cpp}`): bounded MPSC ring,
  `try_push`/`try_pop`, `close()` (producer) / `drop()` (consumer), wake hook.
- **Task** (`src/core/task.{h,cpp}`): C++20 stackless coroutines over the loop
  (`co_task` + `TaskScheduler`), `io::await_readable`, `io::await_timer`,
  spawn/cancel/run_ready. Two bugs fixed in this phase:
  1. `initial_suspend` was `suspend_never`, so the coroutine body ran eagerly at
     the call site (before the scheduler was bound) and spawn then resumed a
     finished frame (UB). Now `suspend_always`; spawn starts the task.
  2. fd/timer callbacks resumed coroutines without the loop bound, so the next
     `co_await` could not register. `resume_one` now always runs inside a loop
     context.
- **util** (`src/util/`): FNV-1a hash, string/path helpers, RFC 4648 base64,
  minimal JSON DOM (zero-copy strings, surrogate pairs, strict keys, error
  positions, SSO-move-safe JVal).
- **Tests**: 7 suites (arena, log, metrics, event_loop, channel, task, util) +
  smoke. Benchmarks registered in `bench_engine`: arena vs malloc, JSON parse.

## Deviations (approved-awaiting)
- **arena_bench speedup landed via design change**: the oldest-first reuse scan
  was O(#blocks) with a cache-missed linked-list walk per allocation (4.2× vs
  malloc). Replaced with a fill cursor that bumps in the current block and
  rewinds to the largest block on reset; every existing block is still reused
  before growth (reset-reuse test unchanged). Result: ~13× vs malloc.
- **`thread_local EventLoop*` in task.cpp** is the only process-global mutable
  state in core/util; it binds the current loop to an executing coroutine
  (required for the `co_await` registration path). Intentional exception.
- Local Release build surfaced `-Werror` `warn_unused_result` on `read`/`write`
  under `-O3` fortify (CI's GCC did not); test now assigns results.
- ASan/LSan cannot run in this proot sandbox (shadow-memory mmap); ASan/UBSan
  asserted on CI in the dev job. 10k-fd soak is deferred to Phase 13 (T2).

## Decisions for later phases
- The `cur_` fill cursor makes `reset()` the memory-truth point; Phase 03+ can
  rely on per-turn arena reuse for zero steady-state allocation.
- `error_code` bool semantics = std::error_code (`if (ec)` means error); callers
  must use `ec.ok()` for clarity (a bench bug here confirmed the footgun).
