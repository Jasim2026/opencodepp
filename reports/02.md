# CHECKPOINT 02 — PASS

**Phase:** 02 Message model, binary codec, token estimator.

## What was done
- **Role & Finish** (`src/msg/role.h`, `src/msg/finish.h`): small enums with
  `to_string` / `from_string`. Roles: `user/assistant/system/tool`; finish
  reasons: `end_turn/max_tokens/tool_use/canceled/error/permission_denied/unknown`.
  `from_string` is a template specialized per enum (`from_string<Role>`,
  `from_string<FinishReason>`) because C++ cannot overload on return type alone.
- **Part** (`src/msg/part.h`): `Part = std::variant<Text, Reasoning, ImageUrl,
  Binary, ToolCall, ToolResult, Finish>`. Each struct carries a `part_kind()`;
  helpers `as<T>`, `holds<T>`, forwarding `visit`, and `part_size_estimate()`
  (string/data bytes + per-object overhead) for budgeting.
- **Message** (`src/msg/message.{h,cpp}`): `Message{id, session_id, role, model,
  parts, created_at}` with `content_text()`, `tool_calls()`, `tool_results()`,
  `is_finished()`, `finish_reason()`. JSON interop `to_json`/`from_json`
  (wire + debug logs only; binary parts ride as base64). `from_json` rejects
  unknown part kinds / bad roles with `e_proto_parse` detail codes.
- **Binary codec** (`src/msg/codec.{h,cpp}`): versioned (v1) compact encoding.
  LEB128 varints; tagged parts; per-message string interning in first-seen
  order (deterministic), so decode → re-encode is byte-identical. `encode_message`
  writes into the caller's arena and returns a span; `decode_message` validates
  every field (role/kind/reason ranges, ref indices, lengths, part-count cap,
  varint bound) and returns `e_proto_parse` with the byte offset, or a
  version-mismatch sentinel. Malformed input can never trigger a huge allocation
  or OOB read.
- **Token estimator** (`src/msg/tokens.{h,cpp}`): `estimate_tokens` is a
  single-pass, allocation-free classifier → prose (words×1.3), code (chars/4),
  or CJK (ideographs×1.1 + ascii/4). `estimate_message_tokens` sums parts with a
  small content-hash memo for repeated strings. Constants live in `tokens.cpp`
  with a comment; the corpus is extensible at `tests/fixtures/tokens/`.
- **Tests**: `msg_test`, `codec_test` (round-trip, determinism, malformed cases
  with exact offsets, truncation sweep, 10k-input fuzz + 2k byte-flip fuzz,
  dedup compactness), `tokens_test` (labeled corpus). Benches added: codec
  encode/decode 500-part, JSON parse of the equivalent document, token estimator.

## Deviations (approved-awaiting)
- **`from_string` became a template** (`from_string<Role>`): the plan's plain
  `from_string(s)` cannot exist twice in one namespace with different return
  types. Template keeps the name and is a recognized idiom; `to_string` stays a
  plain overload (distinguished by parameter type).
- **Commit split** honored the plan's DoD: `feat(msg): parts/message`,
  `feat(msg): binary codec`, `feat(msg): token estimator` — each intermediate
  commit builds (CMake/bench staged incrementally).
- **decode parts-reserve hint**: capped at 512 slots so a hostile `part_count`
  varint cannot force a giant pre-allocation (≤ ~57 KB) while still avoiding the
  realloc copy that cost the 8x gate (7.9x -> 9.4x).
- Token-count labels are hand-set BPE approximations (prose words×1.3, code
  chars/4, CJK ×1.1) because no BPE tokenizer runs in this sandbox; the
  estimator's regime classifier is what the corpus really pins down. Constants
  are centralized for retuning when a real tokenizer lands (Phase 6).
- Local builds only used for pre-push sanity (per local constraints); CI is
  authoritative.

## Decisions for later phases
- Storage uses the binary codec (compact, deterministic, versioned); JSON is
  wire/debug only. Any layout change bumps `kCodecVersion` — version byte is
  first, never change it in place.
- `part_size_estimate()` is the budgeting primitive Phase 06 (budget) and the
  store will call; `estimate_tokens`/`estimate_message_tokens` drive T1 budgeting.
- Codec validation maps to `Err::e_proto_parse` (ABI `OPENCODE_ERR_VALIDATION`)
  so Phase 05 providers and Phase 11 memory reuse the same error vocabulary.
