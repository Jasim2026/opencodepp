# CHECKPOINT 03 — PASS

**Phase:** 03 Config, model catalog, store.

## What was done
- **Config** (`src/config/config.{hpp,cpp}`): `Config{providers, agents,
  network{timeout_ms,max_retries,backoff_base_ms,backoff_max_ms,jitter},
  budget{max_tokens_per_task}, data_dir, context_paths, edge_mode}` loaded from
  a JSON string or a file. Every value is type- and range-checked (bad values ->
  `Err::e_invalid_cfg`, ABI OPENCODE_ERR_VALIDATION, with the field path logged);
  unknown keys log a warning and are skipped, so newer/older configs stay
  loadable. Schema versioned (`kConfigSchemaVersion=1`; newer -> rejected,
  older -> warning).
- **Env snapshot** (`src/config/env_snapshot.{hpp,cpp}`): cached probes for
  platform, arch, shell, git repo/branch/dirty, free_mem_mb, load_avg. Every
  probe is non-blocking (reads `/proc` + `.git` metadata, libc values only; no
  subprocesses). Built lazily, cached; `env_snapshot_invalidate()` forces a
  rebuild and `env_snapshot_build_count()` proves the caching in tests.
- **Model catalog** (`src/model/catalog.hpp`): constexpr table of 11 models
  across anthropic/openai/google plus 3 providers (id, api_family, base_url).
  Each row: id, provider, wire name, cents-per-1M in/out/cached, context
  window, default max tokens, reasoning + attachment flags. Aliases resolve via
  `canonical_id()`; `cost_estimate()` is integer-only ceiling math. Prices are
  date-stamped 2025-10 in the header and centralized for retuning.
- **Store** (`src/store/store.h` + backends): `Store` interface per
  03_ARCHITECTURE.md Section 4 (sessions, ordered per-session messages, file
  versioning) with a no-op-by-default `StoreListener` hook (instance member,
  no globals). `MemStore` is the zero-dependency default, instance-scoped,
  single-mutex single-writer, runs a full session with no files on disk (T2
  embeddability). `SqliteStore` is the durable optional backend behind
  `OPENCODE_USE_SQLITE=ON` (OFF by default; only `sqlite_store.{hpp,cpp}`
  include `<sqlite3.h>`): WAL, `PRAGMA user_version=1`, prepared statements,
  messages stored as binary-codec BLOBs so sessions reload byte-identical.
- **Tests**: `config_test`, `model_test`, `store_test` (shared suite run
  against mem always + sqlite when built; 50-message synthetic session with
  mixed parts that must reload byte-identical, across an sqlite reopen).

## Deviations (approved-awaiting)
- **`catalog.hpp` is header-only** (no `catalog.cpp`): constexpr tables and
  functions must be visible in every TU that uses them; documented in the
  header. The plan named `catalog.{hpp,cpp}`; the cpp would be empty.
- **`git_dirty` is a staged-change proxy**, not a real `git status`: computed
  as `.git/index` mtime newer than HEAD's. True dirty detection needs a
  subprocess, which the plan forbids ("Never blocking"). Documented in
  `env_snapshot.cpp` and `NOTES.md`.
- **Thread-safety is a single mutex** (single-writer) rather than a
  channel/worker thread: consistent with the architecture's "no hidden
  threads" rule; the Phase 1 channel stays available if a worker is ever
  needed.
- **`message_delete` is O(n) per session** in mem_store (linear scan) and
  O(1) indexed in sqlite. Fine at this scale; noted for Phase 13 scale-out.
- **sqlite requires >= 3.35** (uses `ON CONFLICT ... RETURNING`); the CI
  runner ships 3.45.
- Config uses `Err::e_invalid_cfg` (category config) even for a malformed
  JSON blob (map from the JSON parser's `e_proto_parse`), since a bad config
  file is a config error, not a wire error.
- No Phase-3 benches added: the plan asks none; `bench_engine --quick` is only
  required "if built this phase".

## Decisions for later phases
- Storage is binary codec BLOBs in sqlite (compact + deterministic + versioned);
  sessions reload without any JSON.
- `cost_estimate` (catalog) + `budget.max_tokens_per_task` (config) are the
  Phase 6 budget inputs; `EnvSnapshot` feeds Phase 4 net policy (edge_mode,
  free_mem) and Phase 7 context assembly (shell, git state).
- Config `providers[].default_model` and `agents[].model` use catalog ids, so
  Phase 5 providers resolve them through `find_model`.
- One CI-fix commit (`fix(store): link sqlite3 ...`) landed on top of the four
  phase commits; see NOTES.md for the CMake lesson.
