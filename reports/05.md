# CHECKPOINT 05 — PASS

**Phase:** 05 Provider adapters (wire formats).

## What was done
- **Interface** (`src/provider/provider.h`): `Provider` base (build_request /
  parse_frame / parse_usage / name / supports_native_tools / stream_kind /
  reset_stream) and the normalised `StreamEvent` set the agent loop will
  consume — `TextDelta`, `ReasoningDelta`, `ToolCallDelta`, `ToolCallDone`,
  `MessageStart`, `MessageDone{finish, usage}`, `ProviderError{ec, message}`,
  with typed `as<T>()`/`holds<T>()` and inline `describe()`. Swapping providers
  never changes agent code (Task 1).
- **Anthropic** (`anthropic.cpp`): `POST {base}/v1/messages`, typed SSE
  (`message_start`/`content_block_start|delta|stop`/`message_delta`/
  `message_stop`/`error`), top-level `system`, content-block arrays,
  interleaved text/thinking/tool_use, native `tool_use` + input_json deltas
  stitched per block index, stop_reason map, typed error events
  (rate_limit→e_rate_limit, auth→e_auth) (Task 2).
- **OpenAI** (`openai.cpp`): `POST {base}{path}` default
  `/chat/completions`, Bearer auth, native `tools`/`tool_calls`, role:tool
  tool_results, `stream_options.include_usage`; partial `tool_calls[].function.
  arguments` stitched per index, `finish_reason` map, usage from
  `prompt_tokens_details.cached_tokens` (Task 3).
- **Gemini** (`gemini.cpp`): JSONL endpoint
  `/models/{model}:streamGenerateContent?alt=json&key=`, `contents`/
  `systemInstruction`/`tools`/`generationConfig`, `functionCall`/
  `functionResponse` native tools (call_names map for tool results), thought
  parts→ReasoningDelta, `usageMetadata` (Task 4).
- **OpenAI-compatible** (`openai_compat.cpp`): thin projection of the OpenAI
  adapter with an overridable base URL + path for local/self-hosted endpoints
  (vLLM/Ollama/Together), token budgets kept via the resolved ModelSpec
  (Task 5).
- **Factory + resolver** (`factory.cpp`, `resolver.cpp`): `make_provider`
  dispatches on `ProviderConfig.id` (`anthropic|openai|google|openai_compat`),
  catalog base_url fallback via `model::find_provider`; `resolve_model` does
  exact id → alias → (model_name, provider), unknown → `e_model_unsup` with
  bounded Levenshtein suggestions; `split_url` normalises the origin and strips
  trailing slashes (Task 6).
- **Probe** (`tools/probe.cpp`): CLI that builds a Provider, sends a fixed
  prompt over the real Phase 4 stack (Pool + http1 + SseParser), prints the
  StreamEvent sequence and a meter/usage summary; `--mock` starts an
  in-process plaintext OpenAI-format mock so the whole path runs offline and
  in CI (registered as `probe_mock` ctest) (Deliverable).
- **Contract tests** (`tests/provider_test.cpp` + `tests/fixtures/responses/`):
  golden-byte request fixtures for all four adapters, stream scenarios
  (anthropic interleaved tool-input deltas, openai partial-JSON stitching,
  gemini functionCall JSONL, reasoning/thought parts), negative fixtures (bad
  JSON/unknown event/rate-limit/auth → clean ProviderError), usage parsing,
  resolver suggestions, split_url cases, and a 10k-frame/adapter + truncation
  fuzz loop (Task 7).
- **Wiring**: 6 provider sources into `opencodepp_core`, `provider_test` +
  `probe`/`probe_mock` into CTest (`WORKING_DIRECTORY` = `tests/` for the
  fixtures).

## Deviations
- **Interface returns `core::error_code` with out-params, not the plan's
  `Result<T>` sketch**: the codebase convention since Phase 00 is
  `error_code` + out parameters (01_CORE_ERRORS), so the provider layer follows
  it. The StreamEvent set itself matches the plan exactly.
- **`tools/probe --mock` is self-contained** (in-process mock, same pattern as
  `tools/drill`) rather than requiring the standalone `mock_api` binary: one
  deterministic ctest, no process management. `mock_api --response-file/
  --scenario` remains the standalone peer for manual wire testing.
- **`openai_compat` reuses the OpenAI wire code verbatim** (thin projection,
  not a subclass): the compat adapter is a separate TU wrapping the same
  request/parse logic with a different base/path default, keeping the factory
  dependency surface minimal.
- **Gemini `stream_kind()` is `jsonl`, others `sse`** — the SseParser's JSONL
  mode (newline-delimited) is what the Gemini endpoint actually streams, so the
  provider exposes it instead of forcing SSE framing.
- No ASan locally (proot limitation, see NOTES.md); CI is the sanitizer site.

## Decisions for later phases
- **Phase 10 (agent loop) consumes ONLY `StreamEvent`** — text/reasoning/
  tool deltas accumulate into Message parts; `MessageDone.finish` + usage drive
  the retry/turn logic; `ProviderError` (typed `error_code`) maps to session
  error handling. Swapping providers is a config change.
- **Error mapping is fixed and provider-agnostic**: 429→e_rate_limit,
  401/403→e_auth, other 4xx/5xx→e_provider_err, malformed frames→e_proto_parse
  (non-retryable). Retry policy (Phase 4) applies unchanged at the net layer.
- **`Budget`/`ModelSpec` are the Phase 6 seams**: budget projection on the wire
  is done (max_output_tokens); the full token budget machinery lives in
  `src/prompt/`. `ToolSpec` (id/name/description/schema) is the Phase 8 tool
  registry's wire projection — the registry will fill `ToolsSpec`.
- **`tools/probe` doubles as the manual integration fixture**: pointing it at a
  real base_url + key exercises build_request → wire → SSE → StreamEvent with a
  live key when one is available (recorded against `--mock` numbers above).
- **`openai_compat` is the default local-dev adapter** (vLLM/Ollama): no key,
  plaintext, configurable path; token budgets stay honest via the resolved
  ModelSpec (unknown models use config-provided costs).
