# CHECKPOINT 06 — PASS

**Phase:** 06 Prompt architecture and context assembly.

## What was done
- **Prompt representation + compiler** (`src/prompt/compiler.{h,cpp}`,
  `registry.{h,cpp}`): `PromptRef` is a precompiled, immutable prompt — parts
  `[system|template|tools]`, size estimate, and a 40-hex sha1 pinned to the
  source text; the compiler parses the single `{{PLACEHOLDER}}` mechanism
  (deduped, in-order), and compiles files via `compile_prompt_file`
  (`e_missing_cfg` when unreadable). `PromptRegistry` (add-replace / find /
  ids) + `load_templates(dir)` compile every `*.md` keyed by file stem
  (`std::filesystem`, non-recursive). No runtime templating libraries.
  `src/util/sha1.{h,cpp}`: streaming RFC 3174 SHA-1 (64-byte blocks, pad
  `0x80` + 64-bit bit length), verified against the RFC vectors (Task 1).
- **Prompt sources** (`src/prompt/templates/`): `README.md` (only prompt text
  lives here; no code), `SYSTEM_BASE.md` (identity, output contract, coding
  rules, gate protocol, no-explanation/no-preamble), `SYSTEM_VERIFY.md`
  (verification protocol that cooperates with the Phase 9 gates — never blind
  retry, dedupe feedback, abort-and-report on budget exhaustion),
  `SYSTEM_MEMORY.md` (session/workspace memory protocols for Phase 11),
  `TOOLS.md` (tool schema slot filled by the assembler),
  `EXAMPLES.md` (minimal few-shots) and `CODE_STYLE.md` (`{{LANG_STYLE}}`)
  (Task 2).
- **Context assembler** (`src/prompt/context.{h,cpp}`): `assemble_context`
  builds a deterministic `ContextPlan{messages, estimated_tokens, bytes,
  events, omitted, truncated, tools, tool_tokens, under_target}`.
  Tier 1 (always): system core + tool-schema cost + newest user message (and
  every message from the Nth-newest assistant turn onward — the window fix
  below) + last N assistant turns. Tier 2 (budget-gated, fixed order):
  older history, env snapshot, repo snippets (Phase 7 feeds graph-derived
  text), style/examples. Tier 3 (never by default): full-file snapshots.
  Budget: target 3,500 / hard cap from config (default 12,000) / model
  window (context_window − max_output), with a **floor** (`kNewestUserFloor`
  = 800) so the request is never starved; the newest user message is
  **truncated tail-kept**, never omitted; every cut becomes a `ContextEvent`
  and is summarized in `omitted`/`truncated` (Task 3).
- **Budget meter** (`src/prompt/budget.{h,cpp}`): `caps_for(model)` resolves
  per-request caps from the catalog (context_window, default_max_tokens) and
  config; `budget_floor` enforces the correctness floor; `make_budget`/
  `consume` track per-task tokens against `max_tokens_per_task`;
  `project_cost` uses catalog prices via `model::cost_estimate`; the retry
  hook `retry_allowed(budget, ec)` grants retries only for retryable errors
  AND under the reserved retry allowance (`e_budget` is the surfaced
  exhaustion signal, per the error vocabulary) (Task 4).
- **Golden prompt tests** (`tests/prompt_test.cpp` +
  `tests/fixtures/prompts/`): sha1 RFC vectors; compiler placeholder
  discovery + determinism; registry add/replace/load; `tools_schema_json`
  compared byte-normalized against all four Phase 5 request fixtures'
  `tools` arrays (anthropic / openai / google / openai_compat); context
  assembly (tiers, omissions, tail-kept truncation, error paths); budget
  caps/floor/consume/cost/retry hook; and a **corpus** of three fixtures
  (edge profile, code task with a native tool, big-history trim) asserting
  determinism (identical plan on re-assembly), required-part presence (newest
  user message + system core — 100% locally, gate ≥ 95%), token budget, and
  that every cut is a logged `ContextEvent` (Task 5 + Deliverable).
- **`tools/bench_prompt`** (Deliverable): loads the templates, prints each
  template's token estimate + sha1, then assembles the corpus contexts and
  prints tokens/bytes/tiers/cuts — the T1 measuring tool.
- **Wiring**: 5 prompt sources + `util/sha1.cpp` into `opencodepp_core`,
  `prompt_test` into CTest (`WORKING_DIRECTORY` = repo root so both
  `src/prompt/templates` and the fixture dirs resolve), `bench_prompt` into
  tools.

## Acceptance gate results (12_PHASE_06.md)

- [x] **Tool schema output validates against all three provider contracts
      (golden fixtures)**: `tools_schema_json` (anthropic / google / openai +

      `tests/fixtures/responses/*_request.json`.
- [x] **Budget meter: 3-turn retry storm hits the `ERR_BUDGET` report path
      without lowering an edit's quality**: `retry_allowed` returns false for
      non-retryable codes, when the budget is exhausted, and when
      `attempts >= max_attempts`; `consume` refuses over-budget reservations
      and `is_exhausted` flips. The agent loop (Phase 10) is where the loop
      stops and surfaces `e_budget` — the meter stops cleanly, it does not
      degrade silently.

## Deviations
- **Commit split** differs slightly from the plan's suggested message list:
  `feat(prompt): template compiler, registry, provider-native tool schemas`
  (compiler+registry+templates), `feat(prompt): tiered context assembler +
  T1 token/retry budget` (context+budget), `test(prompt): ... suite`,
  `build: ...`, `fix(prompt): Tier-1 window`, `test(prompt): golden prompt
  corpus`, `tools(bench): bench_prompt`. All four plan areas are covered.
- **`tools_schema_json` targets the native `tools` parameter**, and in native
  tool mode the assembler does NOT inject the schema text into messages (that
  would double-count tokens) — the schema cost is still accounted in
  `tool_tokens` and the `{{TOOLS_SCHEMA}}` slot is only filled in prompt-mode
  fallback (`inject_tool_schema`).
- **No runtime binary blob embedding yet**: compilation happens at startup
  from `templates/` (offline-ish, sha1-pinned); embedding a cached blob into
  the binary is deferred to the packaging phase (the compiler API already
  supports it).
- **`bench_prompt` is a manual tool, not a ctest** — it feeds T1 measurement;
  it would need a fixed repo-root argument to be a reliable ctest.
- No ASan locally (proot limitation, see NOTES.md); CI is the sanitizer site.

## Decisions for later phases
- **Phase 7 (graph) feeds `ContextInput.repo` snippets** — the assembler
  already budgets them as Tier 2 in fixed order; the graph just supplies
  `FileSnippet{path,text}`.
- **Phase 9 gates pair with `SYSTEM_VERIFY.md`** — the template text (never
  blind retry, feedback dedupe, abort-and-report) is the prompt-side contract
  the gates enforce in code.
- **Phase 10 consumes `ContextPlan` only** — the agent loop builds messages
  via `assemble_context`, tracks the task with `TokenBudget`/`consume`, and
  surfaces `e_budget` when the meter refuses; `ContextEvent`s stream to hosts
  so every cut is visible.
- **Prompt text is frozen here**: all future prompt edits happen in
  `src/prompt/templates/` and are re-pinned by `prompt_test` (sha1 + token
  estimates); the grouped-codebase "prompts in one place" requirement is met.
