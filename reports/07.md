# CHECKPOINT 07 — PASS

**Phase:** 07 Code graph (symbol index + call graph + targeted context).

## What was done
- **Index core** (`src/graph/index.{h,cpp}`): `SymbolIndex` with position-based
  `SymId`s (removal tombstones, ids stay stable), `by_name_` map for lookup,
  `extract_into` (assigns ids after sym/dep counts are known, resolves
  same-file `to_sym`), `snippet()` (declaration + capped body region),
  `detect_lang` (.c/.cpp/.cc/.cxx/.h/.hpp/.../.go).
- **Extractors** (`src/graph/symbols.cpp`): `extract_lang` — a single-pass line
  scanner (no `std::regex`): one byte-for-byte "code mask" blanks comments and
  string/char literals (offsets preserved), then lines are classified against a
  small keyword/prefix grammar. C/C++: `#include` (raw text), `#define`
  macros, `struct/class/enum/union` types, `typedef`, namespaces, function
  definitions via `try_cpp_def` (first `name(` whose `)` is followed by `{`
  before `;` on the same line; name extended over `::`), globals, and call
  sites on every `(` — each attributed to the enclosing def
  (`from_sym = local def index + 1`, offset by extract_into). Go: `package`,
  imports (single + block), funcs/methods (receiver + generics-bracket skip),
  types, var/const, method/visibility post-pass, same call attribution. Defs
  are appended FIRST per file so a def's file-local index == its position in
  the defs list. Documented fallback limitation: a def must have its signature
  and `{` on the same line.
- **Call graph** (`src/graph/callgraph.cpp`): 1-hop `callees(id)`,
  `callers_of(id)`, `callers_of_name(name)`; deps stored by value with lazy
  cross-file resolution (`to_sym` filled for same-file callees only).
- **Targeted context** (`src/graph/queries.cpp`): `snippet_for_call(file,
  name)` (callee snippet + one small level of callees) and
  `context_for_change(files)` (symbols touched + 1-hop callers), both capped by
  `IndexLimits.context_total_bytes` (16 KB default) and per-snippet bytes.
- **Lazy / incremental** (`src/graph/lazy.cpp`): `ensure_indexed(file)` parses
  only when the `(mtime,size)` fingerprint (nanosecond mtime) changed; the
  parse cache is LRU-capped (`IndexLimits.cache_files` = 256) with touch-clock
  eviction.
- **Index maintenance is O(entries of the touched file), not O(total)** (the
  real perf fix): fresh-file parses skip the redundant full-array `remove_file`
  scan; removal tombstones syms/deps by their recorded ranges; deps keep
  tombstones so range offsets never drift, reclaimed lazily by
  `maybe_compact_deps()` (amortized O(n)); `ensure_indexed` reads each file
  once (`open`+`fstat`+`mmap` in a single fd lifetime) instead of stat-then-
  re-read, and passes the already-read text to the extractor. Tombstoned deps
  are filtered out of `callees`/`callers` queries. Bench on this sandbox: 7.4s
  → ~0.7–1.1s for 1k files, ~0.12s for 200 files.
- **Wiring**: graph TUs into `opencodepp_core`, `graph_test` into CTest
  (WORKING_DIRECTORY = repo root), `bench_graph` into tools.
- **`tools/bench_graph`**: generates N synthetic C files (12 fns × 4 calls
  each), indexes via the lazy path, prints build_ms/syms/deps/files/RSS;
  corpus on tmpfs (`/dev/shm`) when available so timing isolates indexing
  compute from filesystem I/O.

## Deviations
- **Commit split** differs from the plan's suggested list (feat: index+
  backend-interface / c-cpp-go backends / callgraph+queries / lazy rebuild);
  actual: `feat(graph): symbol index + regex extractors + call graph + lazy
  reparse + targeted context`, `test(graph): ... suite + workspace fixtures`,
  `tools(bench): bench_graph`, `fix(graph): scratch tmpdir in graph_test`,
  `perf(graph): line-scanner extractors + O(k) index maintenance`,
  `tools(bench): tmpfs corpus`, `perf(graph): mmap reads`. All plan areas are
  covered.
- **Regex-fallback is now a line scanner, not regexes** — the plan's
  "regex-fallback" survives only as the masker+grammar fallback behind
  `extract_lang`; it was rewritten to hit the 500 ms gate (regex passes were
  3.9 ms/file; scanner is 0.1 ms/file at -O3).
- **`dep_first`/`dep_count` in `ParsedFile` are currently bookkeeping only** —
  consumed by `remove_file` (range tombstoning) after the perf change; they
  were previously set but never read.
- **deleted deps are tombstoned (not erased)** to keep range offsets stable;
  memory stays bounded via lazy compaction when dead deps ≥ live deps (and
  total ≥ 8192). Syms were already tombstoned by design.
- **Local ASan unavailable** (proot limitation, see NOTES.md); CI dev preset is
  the sanitizer site.
- **Tree-sitter backend not built** (OPENCODE_USE_TREE_SITTER off in all
  presets); the interface (`extract_lang`) is the slot it would fill.

## Decisions for later phases
- **Phase 9 (verification) consumes `callees`/`snippet_for_call`** for gate
  inputs — 1-hop is the depth gates need; deeper traversal is caller-side
  (each hop is a lookup).
- **Phase 6 Tier 2 feeds `ContextInput.repo` from `snippet_for_call` /
  `context_for_change`** — the graph supplies `FileSnippet{path,text}` under
  the assembler's budget.
- **The fallback limitation is documented, not papered over**: multiline
  signatures are not defs. If Phase 13 shows recall below target on real
  code, extend the scanner (not relax the gate); tree-sitter remains the
  optional upgrade behind the same interface.
- **`snippet()` re-reads the file on demand** (mmap) — the trade for not
  caching bodies; snippet pinning is deferred to the memory/hardening phase.
