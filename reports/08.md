**Phase:** 08 Tools (native, safe, streamed).

## What was done
- **Tool model** (`src/tools/tool.h`): `ToolSpec` (id, name, description, params_schema,
  is_read_only, category, params), `ToolResult` (status ok/error/canceled, content,
  content_is_error, usage_estimate), `Invocation` (tool_name, args_json, span_id),
  `CancellationToken` (atomic), `ToolProgress` (span_id, phase, chunk, percent),
  `ToolContext` (span_id, cancel, on_progress), `Tool` interface.
- **Schema generator** (`src/tools/schema.{h,cpp}`): `make_spec` computes params_schema
  from `ParamSpec` list; `params_schema()` emits JSON Schema; `tools_json()` projects
  onto OpenAI / Anthropic / Gemini wire families. Golden-byte cross-validated against
  the Phase 5/6 fixture files (openai=171B, anthropic=142B, google=167B for `add(a,b)`).
- **Tool registry** (`src/tools/registry.{h,cpp}`): `ToolRegistry::add/find/all/specs/run`,
  `register_defaults` with `RegistryOptions{workspace, graph, include_write}`. Read-only
  tools are safe to retry/parallelize; write tools gated + serialized. Duplicate wire
  names rejected with `e_invalid_cfg`.
- **Core tools** (`src/tools/exec/`):
  - `util.{h,cpp}`: `resolve_in_sandbox` (lexical normalization, escapes refused),
    `read_whole_file`, `write_file_atomic` (tmp+rename), `file_exists`, `split_lines`
    (fixed trailing empty element), `join_lines`, `glob_match` (fnmatch-lite), `run_process`
    (POSIX fork/exec/poll/kill), `ArgReader`, `sym_to_json`, `snippet_to_text`.
  - `patch.{h,cpp}`: unified-diff parser with `old_body`/`new_body` preserving ctx/rem
    interleaving (bug fix: original parser lost ordering, broke multi-hunk patches);
    atomic apply (all-or-nothing), reverse, apply_file.
  - `read_only.{h,cpp}`: file.read (range/max_bytes), dir.list (recurse+glob), file.stat,
    file.search (regex or glob, gitignore, .git skip, cancellation), workspace.info,
    sym.{lookup,refs,snippet,callees} (graph-aware), git.{diff,status,branch,show}.
  - `write.{h,cpp}`: file.write (overwrite_guard, shadow-copy rollback), file.patch
    (reverse support, atomic apply).
  - `shell.{h,cpp}`: shell.run with ToolProgress streaming (spawn/done phases),
    timeout-kill, cancellation token support, working_dir resolution.
- **Permission gate** (`src/tools/permission.{h,cpp}`): `Gate` class with per-category
  `Policy` (deny/ask/allow/allow_readonly), `PermissionCallback` for ask policy,
  `check()` + `run()` dispatch wrapper. Denial returns `ToolResult{error,
  "permission_denied"}` — never a silent no-op.
- **Bug fixes** (discovered during testing):
  - `patch::apply` lost ctx/rem interleaving → added `old_body`/`new_body` to Hunk,
    match/replace on ordered bodies.
  - `split_lines` produced a spurious trailing empty element on input ending with `\n`,
    causing `join_lines` to double the trailing newline (one-char fix: `pos < text.size()`).
  - `exec/util.cpp`: `split` delimiter char vs string_view mismatch, unqualified
    `now_mono_ms`.
  - `read_only.cpp`/`write.cpp`: missing `#include "tools/schema.h"`.
  - `patch.cpp`/`util.cpp`: hidden Unicode arrows (`→`) in comments → CI hygiene failure.

## Deviations
- **`split_lines` contract changed** from producing a trailing empty element to
  not producing one. This is a bug fix (the trailing element caused
  `join_lines` to double the trailing newline), not a behavioral change for
  callers that iterate lines. The old contract's claim of round-trip fidelity
  was incorrect.
- **Permission gate is separate from the registry** (the plan suggested the gate
  wraps `ToolRegistry::run` — this is exactly what `Gate::run` does). The gate
  is a standalone class that can be composed with any registry instance.
- **Shell tool uses the existing `run_process` helper** (fork/exec/poll/kill)
  rather than implementing a separate streaming variant. The progress events
  are emitted at spawn/done phases; real-time stdout streaming (byte-by-byte
  progress) is deferred to the Phase 10 agent when the need arises.
- **Local build verification is TU-compile + one-shot link only** (low-RAM rule
  from Phase 07); CI is authoritative for the full build matrix.

## Decisions for later phases
- **Phase 9 (verification) uses `Gate` as the enforcement point**: the verify
  gate can wrap or replace the permission gate's `check()` with its own
  semantic-diff validation before allowing writes.
- **Phase 10 (agent) owns `CancellationToken` per span**: the agent creates
  one token per tool invocation and cancels it from any thread when the turn
  is superseded.
- **Shell streaming can be upgraded** to per-line progress when the agent
  (Phase 10) needs real-time stdout feedback; the `ToolProgress.phase` field
  already supports arbitrary phase names.
