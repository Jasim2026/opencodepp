## What was done

Five commits implementing the Phase 11 memory layer:

1. **Entries** (`cfc338a`) — `memory/entry.h` model
   (`Kind {Decision, Fact, TaskState, RepoRule, Lesson, UserPref}`; fields
   `id, kind, scope, key, value, source, created_at, ttl_s, tags`), entry
   JSON serialization, `validate_entry` (value/key length caps from config),
   secret filter (blocks entries containing `token`, `password`, `secret`,
   `sk-…` at write time), `memory` config block
   (`max_value_chars`, `max_key_chars`, `max_entries`, `max_entries_per_task`).

2. **Session checkpoint/resume** (`87e3d7a`) — `memory/session_memory.cpp`:
   `checkpoint()` upserts the session row, message history, and three
   `task_state` entries (`applied_edits` JSON array, `tokens_used`, and
   `workspace_hash`) under `session:<id>` scope; `resume()` reloads them and
   re-hashes the workspace to verify it still matches (stale if changed).
   Wired into the agent loop via `Agent::checkpoint(applied_edits)` after each
   tool round and at task end.

3. **Workspace memory + `memory.write` tool** (`c7f8274`) —
   `memory/workspace_memory.cpp` with `workspace:<root>` scoping, entry
   write/read by kind + tags, keyword matching (no scoring, no embeddings), and
   a ring-buffer cap (reuses the oldest key at `max_entries`). New
   `memory.write` tool (`key`/`value` required, optional `kind`/`tags`)
   registered whenever a store is present. Engine-side extraction at defined
   points: task done → one-line `Lesson` (`lesson_<hash>`, tags from intent),
   gate `permission_denied` → one-line `RepoRule` (`rule_<tool>`). Reads are
   injected into context Tier 2 (`memory:` env var) with a strict budget
   (≤ 6 entries, ≤ 400 tokens).

4. **Summarizer** (`85df4eb`) — `memory/summarizer.cpp`: when message history
   exceeds the context cap, fold the oldest turns into one user-role `Summary`
   message. Deterministic local fold (per-turn first/last line +
   `tool_calls=N`/`tool_results=N`, final `outcome:` line) with an optional LLM
   callback for an in-budget extra call (returns `""` to fall back to local).
   Folding is budget-aware (`needs_fold` uses context window, max output, and
   keep-recent=N); every fold is surfaced as a session `fold` event with folded
   count/reason and an explicit `"; still over the context cap after fold"`
   suffix — never silent truncation.

## Bugs fixed during Phase 11

- **Dangling `string_view` in `entry::to_json` (`225e765`)** — `JVal::Str`
  stores a `std::string_view`; passing `std::string(kind_name(e.kind))` (a
  temporary) left a dangling view that ASan caught as `stack-use-after-scope`
  in `util/json.cpp:258 write_escaped`. Fix: pass the static view directly.
  Introduced in commit 1; **commits 1–3 each failed CI (3/8) on this same
  bug**, and the author mis-recorded the first two runs as green (checked
  `status == "completed"` instead of `conclusion == "success"`). Only the fix
  commit and the summarizer commit are 8/8 green. Lesson: verify
  `conclusion`, not `status`.

## Deviations

- Plan Task 2's session pruning (age/size cap, keep latest N) is **not**
  implemented: `checkpoint()` upserts over the same keys, so session state is
  naturally overwritten rather than accumulated; workspace memory has the
  ring-buffer cap instead. Session-cap pruning deferred to Phase 13.
- Resume is verified by checkpoint/resume round-trip unit tests, not a live
  "kill agent mid-task, reload" drill (deferred to the Phase 13 soak track,
  same `--mock` mechanism as Phase 10's fault-injection suite).
- The `memory ops cost < 1 ms per read` assertion is not committed as a
  timing test (store read path is the Phase 03 store; no timing harness in CI).
- No embeddings / vector search, per the plan (matches "no local ML").
- `tools/run_agent` remains the one-shot task driver; the REPL with explicit
  session resume UX is deferred to Phase 12 (CLI).
