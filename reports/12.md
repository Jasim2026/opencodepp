## Debugging notes (Phase 12 bugs)

- **Raw-newline-in-JSON tool calls.** The Python mock frames embedded a real
  newline inside the tool-call `content` (bytes `\\n` instead of `\\\\n` in
  the literal). The strict proto parser rejected the args
  (`verify invalid file.write: proto_parse`) and the write never ran — yet
  the run still returned OK with the model "finishing" on the error feedback.
  The C++ e2e had used `\\\\n`; the Python tests were the only ones bitten.
  Diagnosed by dumping the mock's request bodies (the tool feedback message
  said `proto_parse`) — not from the event stream.
- **Mock path.** The python test's handler checked `/v1/chat`; the
  openai_compat provider posts to `/chat/completions` → 404 → retries
  exhausted → FAILED. The handler had to match the provider's real path.
- **Event buffer reuse.** The python binding held `opencode_event_t*` and
  read `kind` lazily after `run()` returned → stale/garbage kinds. Fixed by
  snapshotting every field (including a text copy) at callback time.
- **ctypes None callbacks.** CFUNCTYPE slots cannot be assigned `None`
  (`metrics(sink=None)` crashed with ArgumentError); `byref(None)` also
  crashes. The binding now passes a real no-op callback / NULL pointer.
- **ASan-in-dlopened-lib.** The `dev` preset links sanitizers into
  `libopencodepp.so`; Python dlopen then fails ("ASan runtime does not come
  first"). The python CI job builds with the `release` preset.
- **CWD-dependent template load.** Engine configure resolves prompt
  templates relative to CWD; the Java harness ran from `bindings/jni/java`
  → `e_invalid_cfg` on create. Fixed by running `java` from the repo root
  (the same convention as the C++/ABI/e2e tests).
